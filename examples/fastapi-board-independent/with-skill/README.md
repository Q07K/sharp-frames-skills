# Board API

FastAPI + SQLite로 만든 작은 게시판 API입니다. 요구사항은 `REQUIREMENTS.md`를 참고하세요.

## 실행

```sh
# Windows (프로젝트 루트에서)
.venv/Scripts/python.exe -m uvicorn main:app
```

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `BOARD_DB_PATH` | `board.sqlite3` (현재 작업 폴더 기준) | SQLite 파일 경로. 상위 폴더는 미리 있어야 합니다. 테이블은 서버 시작 시 자동 생성됩니다. |
| `SESSION_TTL_SECONDS` | `3600` | 세션 수명(초). 양의 정수가 아니면 서버가 시작되지 않고 `ValueError`를 냅니다. |

API 문서는 서버 실행 후 `http://127.0.0.1:8000/docs`에서 볼 수 있습니다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `main.py` | `uvicorn main:app` 진입점 |
| `board/app.py` | `create_app(settings, clock)` — 라우터 연결, 시작 시 스키마 생성 |
| `board/config.py` | 환경 변수 읽기·검증 |
| `board/db.py` | 스키마, 요청 단위 SQLite 연결 |
| `board/auth.py` | 회원가입·로그인, Argon2 해시, 세션 토큰, `require_user` 인증 의존성 |
| `board/posts.py` | 게시글 CRUD, 입력 검증, 작성자 권한 |

설계상 결정:

- 세션 토큰은 `secrets.token_urlsafe(32)`(256비트)이고 DB에는 SHA-256 지문과 만료 시각(Unix 초)만 저장합니다.
  만료 판정은 DB 조회 조건(`expires_at > now`)으로 하므로 재시작 후에도 동일하게 적용됩니다.
- 사용자 이름 중복은 DB `UNIQUE` 제약으로 판정하므로 동시 가입도 409로 처리됩니다.
- 존재하지 않는 사용자 로그인도 더미 해시를 검증해, 응답 시간으로 사용자 존재 여부가 드러나는 것을 줄였습니다.
- 수정·삭제 순서는 인증(401) → 입력 검증(422) → 존재 여부(404) → 작성자 확인(403)입니다.
- 게시글 ID는 `AUTOINCREMENT`라 삭제된 ID가 재사용되지 않습니다.
- 엔드포인트는 동기 함수(`def`)여서 블로킹 SQLite 호출이 스레드 풀에서 실행됩니다.

## 검사

pytest가 환경에 없어 표준 라이브러리 `unittest`와 FastAPI `TestClient`를 사용합니다(패키지 추가 설치 없음).

```sh
.venv/Scripts/python.exe -m unittest discover -s tests -t . -v
```

- 실제 앱과 임시 SQLite 파일로 테스트하며, 인증·검증·저장은 모킹하지 않습니다. 세션 만료는 주입한 시계로 검증합니다.
- `tests/test_workflow.py`는 두 작성자/비로그인 방문자 흐름을 앱 재시작 전후로 검사하고,
  실제 `python -m uvicorn main:app` 프로세스를 같은 DB로 두 번 띄워 회원·게시글·세션 유지를 확인합니다.
- 요구사항별 케이스는 `tests/CASE_MATRIX.md`에 정리돼 있습니다.

실행 결과(2026-10-21, Windows 11, Python 3.13.8, `.venv`): **28개 테스트 모두 통과**.
Starlette의 `TestClient`가 httpx 사용에 대해 `StarletteDeprecationWarning`을 출력하지만 결과에는 영향이 없습니다.

추가로 확인한 것:

- 라우터가 없는 상태에서 먼저 테스트를 실행해 API 테스트가 404로 실패하는 것을 확인한 뒤 구현했습니다.
- 핵심 규칙을 일부러 하나씩 깨뜨려(작성자 확인 제거, 만료 무시, 추가 필드 허용, 제목 trim 제거,
  토큰 원문 저장, 작성자 ID 고정) 각각 테스트가 실패하는 것을 확인하고 원복했습니다.
- `SESSION_TTL_SECONDS=0`으로 서버를 띄우면 시작 단계에서 오류로 종료되는 것을 확인했습니다.

## 남은 한계

- 로그아웃·세션 폐기 API는 요구 범위에 없어 만들지 않았습니다. 토큰은 만료될 때까지 유효합니다.
- 만료된 세션 행은 로그인할 때 정리되므로, 로그인이 없으면 DB에 남아 있습니다(인증에는 쓰이지 않음).
- 사용자 이름은 대소문자를 구분합니다(`alice`와 `Alice`는 다른 사용자). 요구사항에 정해져 있지 않아 그대로 두었습니다.
- 로그인도 가입과 같은 입력 모델을 쓰므로 형식이 맞지 않는 입력(예: 7자 비밀번호)은 401이 아닌 422입니다.
- 회원가입·로그인 요청의 알 수 없는 추가 필드는 무시합니다(게시글 입력만 422로 거절).
- 스키마 마이그레이션 도구가 없습니다. 테이블 구조를 바꾸면 기존 DB 파일을 직접 옮겨야 합니다.
- SQLite 단일 파일이라 쓰기는 직렬화되며 다중 서버 배포는 고려하지 않았습니다.
- 동시 요청 경합(수정 중 삭제)은 rowcount 확인으로 404를 반환하도록 했지만, 동시 요청 자체를 재현하는 테스트는 없습니다.
- 요청 제한(무차별 로그인 방지), HTTPS, 배포 설정은 범위 밖입니다.
