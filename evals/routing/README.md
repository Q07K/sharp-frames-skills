# 실제 호스트 호출·선택 평가

`../triggers.json`은 예상 선택을 정의한 입력이며 실제 실행 결과가 아닙니다.
[2026-10-21 Claude Code 실행 결과와 한계](claude-code-2026-10-21.md)를 별도로 공개합니다.
기존 구현 대상 10개 요청의 query·기대값은 유지하고, 대상 스킬과 사례 ID를 명시했습니다.
brainstorm·plan·review·help의 긍정·부정 사례를 추가했습니다.
부정 사례는 해당 대상만 선택하지 않을 것으로 기대하며 다른 적절한 스킬은 허용합니다.

## 조건과 입력

같은 호스트 버전·모델·권한·요청·fixture에서 아래 두 조건을 비교합니다.

| 조건 | 스킬 구성 |
| --- | --- |
| 단독 | Sharp Frames와 호스트 기본 스킬 |
| 공존 | 같은 구성에 특정 버전의 Superpowers 추가 |

사용자 전역 설치를 켜고 끄는 대신 각 실행에 독립 폴더를 만들고,
`evals/fixtures/shop` 복사본과 현재 배포 스킬 폴더만 제공합니다.
Claude Code에서는 복사본의 `.claude/skills/<name>/`에 스킬 전체를 배치합니다.
대상 이름·should_trigger·이 문서·평가 결과는 작업 에이전트에게 주지 않고 query만 전달합니다.
실행 전 실제 발견된 스킬과 플러그인을 확인합니다. 기본 `/code-review` 등의 존재와
도구 제한도 기록하며, 프로젝트 설치가 보인다고 전역 설정이 모두 격리됐다고 가정하지 않습니다.

각 query는 새로운 대화와 별도 복사본에서 실행합니다. 이전 결과나 정답을 다음 실행에
보여주지 않습니다. 모델의 실제 스킬 호출·스킬 본문 읽기와 최종 출력, 도구 실패를
보관합니다. 문서에 적힌 이름이나 모델의 자기 보고만으로 선택 성공을 판정하지 않습니다.
여러 스킬을 쓰면 첫 호출과 전체 호출을 모두 기록합니다. 대상이 선택돼도 추가 절차나
불필요한 변경이 발생할 수 있으므로 선택 여부와 작업 수행의 적합성은 구분합니다.

## 직접 호출과 도움말

자연어 query와 별도로 아래 직접 호출을 새 대화에서 검사합니다.

- Codex: `$sharp-frames-help`, `$sharp-frames-review …`
- Claude Code 직접 설치: `/sharp-frames-help`, `/sharp-frames-review …`
- 플러그인 설치: 실제 등록된 `/plugin-name:skill-name`

help는 현재 호스트의 명령 표기·예시, 수정 경계가 맞는지 확인합니다.
등록되지 않은 명령을 있다고 하거나, 도움말 때문에 프로젝트 검사·파일 수정을 수행하면
실패로 기록합니다. 기존/수정 help를 비교할 때도 같은 catalog·요청·호스트 조건의
독립 복사본을 쓰며 두 결과를 서로 보여주지 않습니다.

Windows 스크립트 안내는 실제 Python 실행기에서 두 helper의 `--help`와 관련 도구 검사를
실행하고, `python` 별칭 실패와 helper 자체 실패를 구분합니다. 런타임이 없을 때의
에이전트 대응은 별도 행동 평가이며, 대체 명령이 실행됐다고 그 행동까지 검증한 것은 아닙니다.

## 기록과 해석

호스트·모델·플러그인 버전, 스킬 파일 지문, 입력 복사본, 실행 옵션·권한, 사례별 실제
호출 순서·동시 선택, 명령·원본 출력 위치, 성공·실패·미확인 사유와 실행 횟수를 기록합니다.
인증 실패·한도·권한 거절·네트워크 실패는 대상 미선택과 구분하고 미실행으로 남깁니다.
토큰·시간은 수집된 경우에만 기록하며 누락값을 추정하지 않습니다.

형식 검사는 이 사례의 존재·형식만 검사합니다. 공존 조건에서 대상 미선택이 재현돼도
모든 모델·플랫폼에 일반화하지 않으며, 직접 호출 성공은 자동 선택 성공률이 아닙니다.
단일 실행의 동률·실패와 작은 표본을 공개합니다. 초기 fixture·grader·과거 평가 해시는
변경하지 않고, 실제 결과는 날짜가 있는 별도 결과 문서에 저장합니다.
