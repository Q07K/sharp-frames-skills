# 평가 방법

## 구분

- **패키지 검사:** frontmatter, 참조 경로, 평가 데이터, fixture 실행 가능성.
- **행동 평가:** 실제 요청을 에이전트가 수행한 코드·과정·보고서를 확인.
- **자동 선택 평가:** 실제 사용하는 도구에서 올바른 요청에 스킬이 선택되는지 확인.

세 검사는 서로 대체하지 않습니다. `triggers.json`의 분류를 사람이 검토한 결과는
플랫폼의 실제 자동 선택 성공률이 아닙니다.

## 초기 과제

`evals.json`에 두 요청과 평가 기준이 있습니다. `fixtures/shop`은 외부 의존성이 없는
작은 Python 예제이며 FastAPI/DB 통합 벤치마크는 아닙니다.

1. 기존 주문 가격 정책을 사용하면서 저장하지 않는 견적 서비스 추가.
2. 일반 주문은 유지하고 기업구매 정책만 변경.

각 요청마다 같은 fixture를 별도 폴더에 복사하고 동일한 모델·도구·권한·요청으로
스킬 사용/미사용을 실행합니다. 서로의 결과와 평가 정답을 보지 않게 합니다.
기준 fixture는 수정하지 않고, 실제 수정은 복사본에서 수행합니다.

결과를 확인하는 예:

```sh
python tools/check_fixture.py --case 1 --path /absolute/path/to/candidate
```

동작 검사는 외부에서 정한 예상 금액과 경계값을 사용합니다. 추가로 실제 diff를 읽어
검사 약화, 과도한 추상화, 미연결 코드, 거짓 보고 여부를 검토합니다.
테스트 개수나 수정 줄 수가 많다는 것만으로 높은 점수를 주지 않습니다.

## 해석

두 개의 합성 과제와 한 번의 실행은 스모크 테스트입니다. 성능 향상이나 비용 절감의
통계적 증거가 아닙니다. 둘 다 성공하면 성공했다고 보고하고 차이를 만들어내지 않습니다.
시간·토큰을 수집하지 못했으면 수치를 추정하지 않습니다.

확장할 과제: 실제 FastAPI/DB 통합, 권한 경계, 동시 요청, 기존 실패 테스트, 다른 언어,
큰 저장소에서의 재사용 탐색, 문서만 수정하는 비적용 요청, 작은 변경의 과잉 작업 여부.

개선은 실패를 재현한 뒤 범용적인 지침으로 반영합니다. 평가 과제의 이름·값·정답을
스킬 본문에 넣어 성적을 올리지 않습니다.

## FastAPI 확대 비교

[3개 과제 × 조건별 3회 결과](results/fastapi-2026-10-20.md)와
[재현 가능한 코드·검사·환경](fastapi/README.md)을 추가했습니다.
원래 평가 점수와, 채점 도구 감사 후 추가한 검사는 구분해 공개합니다.
CI는 저장된 결과를 다시 검사하며 AI를 새로 실행하지 않습니다.
