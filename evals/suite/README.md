# 기능별 수용 검사

실행일: 2026-10-20. 새 명령이 요청한 일을 수행하고 수정 경계를 지키는지 확인했습니다.
이것은 스킬 사용·미사용의 품질 우위나 생산성 효과를 비교한 실험이 아닙니다.

4개의 독립 에이전트 실행에 필요한 예제와 스킬만 제공했습니다. 예상 결함·수정 정답·
이전 실행 결과는 주지 않았으며, improve에는 실제 앞선 audit 보고서를 입력으로 제공했습니다.
코어 구현 스킬의 기존 FastAPI 실험과 구분합니다.

| 실행 | 사용 스킬 | 확인한 결과 |
| --- | --- | --- |
| 변경 리뷰·지도 | review, map | 공개 내보내기의 소유권 누락을 실행으로 재현하고, 실제 정책 소유자·호출 경로·재사용 후보를 설명 |
| 부채·효과 | debt, gain | 주석만 삭제된 기존 부채를 유지하고 새 오류 은폐를 구분. 단위 불일치·비용 누락·기준 0을 보수적으로 처리 |
| 도움말·전체 진단 | help, audit | 8개 기능과 수정 경계를 안내. 전체 작은 예제를 조사한 범위·우선순위와 권한 문제를 보고 |
| 실제 개선 | improve | 기존 권한 함수를 재사용해 수정. 원본에서 실패한 독립 공개 호출 검사가 수정 후 통과하고 기존 검사 유지 |

작성자가 실제 보고서·코드·테스트를 읽었습니다. 읽기 전용 3개 실행은 전체 입력 파일의
해시·파일 집합·Git 인덱스와 단일 커밋 이력을 대조해 변하지 않았음을 확인했습니다.
improve는 CLI의 본인/타인/혼합/빈 목록/중복 입력과 알 수 없는 명령을 별도 검사했고,
추가한 테스트를 포함한 7개 테스트도 통과했습니다. 원본 두 테스트 메서드는 유지됐습니다.

gain의 **쿼리 −40% 등 수치는 비교 오류 방지용 합성 입력값**입니다. 실제 프로젝트나
이 스킬의 절감 성과가 아닙니다. 단위가 다른 값을 직접 빼지 않고, 없는 비용을 0으로
채우지 않으며, 기준 0에서 변화율을 계산하지 않는지를 검사한 예제입니다.
입력값의 `measured` 선언은 실제 측정이 일어났다는 인증이 아닙니다.

## 보조 도구

`python -m unittest discover -s tests -v`의 8개 검사는 다음을 확인합니다.

- 부채 후보 탐색: Python 문자열/주석 구분, 무시 파일, Unicode 경로, 추적·미추적 파일,
  literal custom marker, 크기 제한, 실제 파일·Git 상태 보존, Git 실패를 clean으로 처리하지 않음.
- 수치 비교: 실제 델타·방향, 기준 0, 측정 조건·단위·방식 차이, 누락값, 유효하지 않은
  값과 중복 지표, 극단적인 숫자 범위와 CLI 오류 응답.

CI는 이 도구 검사와 카탈로그·문서 일치를 확인합니다. 독립 에이전트를 매 CI마다
실행하거나 실제 자동 선택을 검사하지는 않습니다.

기능이 늘어났다는 이유로 초기 비교에서 확인되지 않은 품질 우위를 주장하지 않습니다.
