# TDD·테스트 무결성·페르소나 흐름 수용 검사

실행일: 2026-10-20. 독립 에이전트에 스킬과 작은 FastAPI/SQLite 저장소를 제공했습니다.
스킬 사용·미사용의 품질 우위 실험이 아닙니다. 세 요청은 새 기능 구현, 테스트만 보강,
미커밋 변경 리뷰이며 서로의 출력이나 외부 채점 자료는 제공하지 않았습니다.

fixture는 실제 운영 서비스가 아닙니다. 인증은 서버의 테스트 세션 표로 대체되며 브라우저·
실제 인증 제공자·결제·운영 DB 격리 수준을 검증하지 않습니다. 사용자별 API 연속 요청과
독립 SQLite 상태를 확인하는 범위입니다.

## 검사 방법

| 사례 | 관측한 결과 |
| --- | --- |
| 신규 기능 TDD | 같은 테스트 코드의 red/green 재실행 확인. 구현 후 자체 10개와 외부 계약 7개 모두 통과, 기존 조회 검사 보존 |
| 테스트만 보강 | 제품 코드는 유지하고 소유권 결함을 실패로 보고. 13개는 정상 참조 구현에서 통과하고 권한·중복 복구·잘못된 상태 허용 변형 세 가지를 모두 검출 |
| green 변경 리뷰 | 8개 수집 중 1개 skip인 성공 suite에서 실제 타인 주문 취소를 재현. skip·넓은 200/409/500 허용·중복 수집의 한계를 설명, 입력 파일 유지 |

unittest의 subTest 실패 수는 메서드 수보다 많을 수 있어 둘을 같은 건수로 세지 않습니다.
외부 계약 검사는 최종 응답 외에 주문·재고 상태, 거부 후 후속 조회, 저장 실패 후 롤백·재시도를
검사했습니다. 동시 반복 요청 검사는 제출 테스트에서 수행했으며 모든 스케줄의 증명은 아닙니다.

- 구현 사례: 제출 테스트의 before/after 자료와 최종 코드를 읽고, 별도 계약 검사로 역할·
  소유권·반복 요청·주문 상태·저장 실패 후 롤백과 복구 흐름을 확인합니다.
- 테스트 전용 사례: 제품 코드를 유지했는지 확인하고, 작성한 테스트를 별도 정상 구현과
  권한·반복 부작용·잘못된 상태 허용 변형에 실행해 결함 검출 여부를 확인합니다.
- 리뷰 사례: suite가 초록이어도 실제 계약 위반을 재현하고 skip·넓은 허용값의 문제를
  구분하는지 읽습니다. 수집된 수와 독립된 계약 수를 같은 것으로 취급하지 않습니다.

외부 계약 검사와 변형은 작업자가 수정하도록 제공한 입력에 포함하지 않았습니다.
파일 시스템 권한으로 악의적 접근을 차단한 적대적 보안 실험은 아닙니다. 같은 작성자가
모든 테스트와 채점 자료를 수정할 수 있는 환경에서 변조 불가능성을 주장하지 않습니다.

독립 재실행으로 실패/통과의 민감도와 스냅샷 내용을 확인할 수 있지만 에이전트의 모든
내부 실행 순서를 암호학적으로 증명하지는 않습니다. 실제 단계별 기록과 재실행을 구분합니다.
채점 도구는 요청 dispatch 후, 제출 결과 열람 전에 작성했으며 사전 등록 비교 실험이 아닙니다.

## 자료와 재실행

[요청과 범위](cases.json), [관측·독립 검사](checks.json), [입력·출력 압축 파일](forward-evidence.zip),
[압축 파일 해시](archive-sha256.txt), [적용 스킬 지문](skill-files-sha256.json),
[리뷰 입력 지문](review-input-sha256.json)을 공개합니다.
개인 경로는 자리표시자로 바꾸고 `.git`·캐시·임시 DB는 제외했습니다. 원래 기준 파일과
검사 단계의 테스트·실행 기록을 보관합니다. 스킬 지문은 LF 기준 UTF-8 텍스트 해시입니다.

```sh
python -m pip install -r evals/fastapi/requirements.txt
python -X utf8 evals/tdd/replay_evidence.py
```

재실행은 저장된 코드·테스트와 외부 검사를 실행합니다. AI를 새로 호출하거나 자동 선택을
시험하지 않습니다. 시간·토큰·사람 검토 시간·운영 성능 효과는 측정하지 않았습니다.
작은 단일 예제와 각 1회 실행으로 모든 예외 검출이나 품질 향상을 보장할 수 없습니다.
