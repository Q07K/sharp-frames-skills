# 짧은 요청: 새 개발 비교와 기존 코드 정리

2026-10-21 실행. 제품 요청은 **`FastAPI로 로그인과 게시글 CRUD API 만들어줘.`**
한 문장입니다. 긴 요구사항 문서, 원하는 아키텍처, 기존 예제나 정답은 제공하지 않았습니다.
이전 [상세 계약 기반 실험](../board-independent/README.md)은 그대로 보존합니다.

## 서로 다른 세 결과

| 결과 | 시작 자료 | 요청 |
| --- | --- | --- |
| A · 미사용 새 개발 | 빈 프로젝트 | 같은 제품 요청 |
| B · 스킬로 새 개발 | 빈 프로젝트 + development | 같은 제품 요청 앞에 스킬 호출 |
| C · 기존 코드 정리 | A 원본 전체 복사 + development | 스킬 호출 + `이 코드 정리해줘.` |

A와 B는 같은 요청의 비교입니다. A→C는 같은 코드의 리팩터링 비교입니다.
B는 처음부터 스킬을 적용한 별도의 개발 결과이며 C의 후속 버전이 아닙니다.
조건별 1회이고, C는 A에 의존하므로 세 독립 표본으로 합산하지 않습니다.

## 제공한 환경과 독립 범위

외부 작업 폴더·가상환경·새 Claude CLI 프로세스를 각각 만들었습니다. 개발 프로세스는
기존 대화, 저장소, 다른 조건의 코드, 외부 검사에 접근하지 않도록 안내했습니다.
같은 OS·인증 계정·공급자를 사용했으며 VM·다른 OS 사용자로 격리한 보안 실험은 아닙니다.
기본 내장 도구/스킬은 양쪽에 같게 노출하고 사용자 플러그인은 끕니다. B와 C에만 프로젝트
스킬을 설치합니다. 자연어 자동 선택이나 Codex에서의 실제 실행을 검증한 실험은 아닙니다.

제품 요청 뒤에는 두 조건 모두 `환경 안내: ENVIRONMENT.md를 읽어줘.`를 붙입니다.
이 파일은 `.venv/Scripts/python.exe`와 미리 설치된 의존성, 작업 폴더 접근 범위만
안내합니다. 기능 명세·폴더 구조·테스트 절차는 없습니다. 제품 요청과 환경 안내를 포함한
실제 프롬프트, 도구 호출, 제출 소스와 실행 기록을 증거에 보존합니다.

Claude Code에서 B와 C의 첫 줄은 `/sharp-frames-development`입니다.
README의 Codex 예시는 같은 요청을 `$sharp-frames-development`로 표기합니다.
실험 모델과 도구 버전은 초기화 기록에서 확인합니다.

## 검사 원칙

[실행 전 프로토콜](protocol.json)과 [스킬·프로토콜 지문](pre-generation-sha256.json)을
생성 전에 고정했습니다. 구체적인 URL·요청 필드·응답 형식은 지정하지 않았으므로,
각 제출물의 공개 인터페이스에 맞게 연결해 같은 기능 흐름을 검사합니다. 이 연결 작업은
생성 후 작성하며 기능 기대값을 결과에 맞춰 바꾸는 데 사용하지 않습니다.

가입 또는 제공된 계정으로 로그인하고 글 작성·목록·단건 조회·수정·삭제를 실제 HTTP로
확인합니다. 익명 쓰기·잘못된 비밀번호·다른 작성자의 변경 거부와 상태 보존은 별도의
안전성 관측입니다. 짧은 요청에 없었던 세부 상태 코드나 폴더 모양을 실패 기준으로 삼지 않습니다.

C를 실행하기 전에는 A의 원본 소스, 자체 검사와 OpenAPI, 외부 흐름 검사를 고정하고
동일 검사를 A와 C에 적용합니다. 생성 코드의 실패를 운영자가 고치거나 결과가 좋을 때까지
재생성하지 않습니다. 자체 테스트 수는 서로 다른 기준이라 품질 점수로 비교하지 않습니다.

## 관측 결과

Claude Code **2.1.292**, **claude-opus-5-5**, Python **3.13.8**, Windows에서 실행했습니다.
세 환경 모두 같은 28개 패키지가 설치됐습니다. 조건마다 한 번 실행했고, 세 요청은 모두
추가 사용자 답변 없이 파일 생성 또는 정리를 마쳤습니다. 소스는 운영자가 수정하지 않았습니다.

| 검사 | A · 미사용 | B · 새 개발 + 스킬 | C · A 정리 + 스킬 |
| --- | --- | --- | --- |
| 최초 공통 HTTP 흐름 | 6/6 통과 | 6/6 통과 | 6/6 통과 |
| A의 원본 OpenAPI | 고정 | 별도 계약 | 일치 |
| 수정하지 않은 A의 테스트 | 8/8 통과 | 별도 계약 | 8/8 통과 |
| 각자 제출한 자체 테스트 | 8/8 통과 | 41/41 통과 | 9/9 통과 |
| 성공 응답 직후 강제 종료·재시작 (사후 10회) | 0/10 통과 | 10/10 통과 | 10/10 통과 |

공통 흐름의 첫 네 그룹은 사전에 정한 로그인·CRUD, 잘못된 비밀번호, 익명 쓰기 거부,
다른 작성자 변경 거부와 상태 보존입니다. **위조 토큰 거부와 재시작 후 보존은 제출물 확인 후
추가한 탐색 검사**이며 사전 등록된 점수로 해석하지 않습니다. 모두 실제 Uvicorn 서버와
별도 DB를 사용했습니다. 자체 테스트의 범위와 파라미터 수가 다르므로 개수를 품질 점수로 쓰지 않습니다.

최초 replay에서는 A의 재시작 보존 검사가 실패했습니다. [첫 재실행 관측](first-replay-observation.json)을
남겼으며, 최초 통과 결과를 덮어쓰지 않았습니다. Windows의 `process.terminate()`는 프로세스를
강제 종료합니다. 성공 응답을 받은 직후 종료하면 A의 응답 후 commit이 끝나기 전에 중단될
수 있습니다. B는 핸들러에서 commit하고 C는 `scope="function"`으로 응답 전에 commit합니다.
[같은 검사의 사후 10회씩 반복 기록](restart-observations.json)에서 A 0/10, B/C 10/10을
관측했습니다. 이것은 같은 제출물에 대한 반복 검사이며 새로운 구현 표본 10개가 아닙니다.
다른 OS의 정상 종료와 동일한 조건으로 일반화하지 않습니다. 고정한 검사나 원본을 고치지 않았습니다.

A도 라우터·DB·인증·모델을 분리하고 작성자 판단을 재사용했습니다. B는 앱 생성 함수로
설정을 받으며 인증·게시글 테스트와 케이스 표를 작성했습니다. C는 A의 폴더를 유지하면서
DB 의존성 선언과 인증 실패 응답을 재사용하고 초기화 연결 수명과 commit 응답 순서를 고쳤습니다.

C가 추가한 `test_failed_commit_is_not_reported_as_success`는 commit이 실패할 때
500과 데이터 미저장을 기대합니다. 운영자는 **같은 테스트를 수정하지 않고** 별도 임시 파일에
복사해 A에서도 실행했습니다. A는 기대한 500 대신 201로 실패했고, C의 검사는 통과했습니다.
이것은 정리 과정에서 발견한 **사후 회귀 사례**입니다. 단순 코드 정리 외에 오류 응답 동작을
바꾼 수정이며, 생성 전에 고정한 A/B 품질 점수나 독립 표본으로 합산하지 않습니다.

세 자체 검사에서 `starlette.testclient`의 httpx 사용에 대한 deprecation 경고가
관측됐습니다. 고정한 실험 의존성을 바꾸어 숨기지 않았습니다. 동시성·부하·실배포·브라우저
검사는 하지 않았습니다. 외부 흐름이 모두 성공했다는 결과가 모든 상태와 안전성을 증명하지는 않습니다.

초기화 정보, 공개 도구 호출과 Bash 출력, 최종 응답·사용량과 운영 스크립트가 있습니다.
로그의 개인 경로는 치환했고 내부 사고 내용은 포함하지 않았습니다. 소스는 치환하지 않았습니다.
지문은 변경 확인 자료이며 보안 격리나 독립적인 서명 검증을 제공하지 않습니다.

```sh
python -m pip install -r examples/fastapi-short-prompt/without-skill/requirements.txt
python -X utf8 evals/short-prompt/replay.py
```

의존성을 설치한 동일 Python으로 실행하세요. 재실행은 ZIP·원본·고정 검사 지문을 확인한 뒤
HTTP 결과 20개(공통 18 + A/C 계약 비교 2), 자체 검사, 원본 8개 검사의 유지,
사후 commit 회귀를 실행합니다. **A의 재시작 경합 때문에 최초 결과와 달라지면 실패를
표시하고 비정상 종료합니다.** 실패를 통과로 간주하지 않으며, 이 변동이 있는 실험을
필수 CI에 추가하지 않았습니다. 모델을 다시 호출하거나 소스를 고치지 않습니다.

최종 전체 재실행에서는 A가 공통 흐름 5/6(계약 비교를 포함하면 6/7), B는 6/6,
C는 계약 비교 포함 7/7이었습니다. 기존 검사 유지와 사후 commit 회귀도 재현했고,
A의 차이를 실패로 남겨 명령은 exit 1로 끝났습니다.

```sh
python -X utf8 evals/short-prompt/diagnose_restart.py --output restart-local.json
```

한 과제의 결과로 일반적인 품질 향상·비용 절감·권한 보안을 보장할 수 없습니다.
측정하지 않은 유지보수 비용이나 개발 속도는 수치로 주장하지 않습니다.
