# FastAPI 확대 비교: 추가 품질 향상은 확인되지 않음

평가일: 2026-10-20. 평가 대상: 초기 공개 버전 `19a2b7a`의
`maintainable-development`. **현재 실험으로 스킬의 일관된 품질 우위를 주장할 수 없습니다.**
스킬을 쓰지 않은 결과도 같은 외부 기능 검사를 모두 통과했고, 이름을 가린 코드 비교도
우세 방향이 일관되지 않았습니다. 우위가 없다는 일반적 증명도 아닙니다.

## 무엇을 실제로 실행했나

동일한 FastAPI·SQLite 초기 코드를 사용해 서로 다른 과제 3개를 조건별 3회,
총 18회 실행했습니다. 매 실행은 이전 대화를 받지 않는 새 에이전트였고 모델·추론 설정
변경을 요청하지 않았습니다. 기본 에이전트 지침은 양쪽에 동일하게 적용됩니다.
한쪽만 고정된 스킬과 필요한 참고 자료를 읽게 했습니다.

| 과제 | 스킬 사용: 외부 검사 전부 통과 | 미사용: 외부 검사 전부 통과 |
| --- | --- | --- |
| 실제 주문과 같은 금액을 반환하고 저장하지 않는 견적 API | 3/3 | 3/3 |
| 권한·멱등성·동시 재시도·롤백이 필요한 취소 API | 3/3 | 3/3 |
| 권한·필터·전체 건수·페이지 처리가 필요한 목록 API | 3/3 | 3/3 |
| 합계 | **9/9** | **9/9** |

차이는 0회, 관찰된 검사 통과율 차이는 0%p입니다. `complete_success`라는 JSON 필드는
선택한 외부 검사 전부 통과를 뜻하며, 과제 전체의 무결함을 보증하는 필드가 아닙니다.
기존 테스트는 후보 결과물 밖의 원본 복사본에서 실행해, 후보가 검사를 약화해도 우회하기
어렵게 했습니다. 미구현 원본은 새 기능 검사에 실패했습니다. 후보가 직접 작성한
테스트 모음 18개도 별도로 다시 실행해 모두 통과함을 확인했습니다.

## 코드 검토에서는 무엇이 달랐나

두 명의 독립 AI 검토자에게 조건 이름과 동작 검사 결과를 주지 않고, 무작위 A/B 이름의
9쌍을 비교하게 했습니다. 공통 기준은 정책 재사용, 변경 범위·책임, 가독성·계약,
검증·보고의 충실도였습니다. 테스트·타입·파일 개수 자체로 가점을 주지 않았습니다.

| 검토자 | 스킬 사용 쪽 우세 | 미사용 쪽 우세 | 동등 |
| --- | --- | --- | --- |
| 1 | 0 | 0 | 9 |
| 2 | 2 | 1 | 6 |

두 검토자는 6쌍에서 동등 판정에 일치했습니다. 나머지 3쌍은 검토자 1이 동등으로 본
차이를 검토자 2가 특정 테스트의 실질적 보강으로 평가한 경우입니다.
검토자 2의 우세 판정은 세 번 모두 B 쪽이었으며, A/B를 뒤집은 추가 검토는 하지
않았습니다. 따라서 위치에 따른 편향도 배제하지 못합니다.

- **사용 쪽 우세 사례, 취소 2회차:** 서로 다른 주문에 같은 키가 동시에 쓰이는 충돌과
  여러 쓰기 단계의 실패를 더 직접적으로 검증했습니다.
- **미사용 쪽 우세 사례, 취소 3회차:** 여러 상품 중 뒤쪽 상품에서 실패할 때 앞선 변경도
  롤백되는지, 서로 다른 충돌 요청이 동시에 들어오는지를 더 직접적으로 검증했습니다.
- **사용 쪽 우세 사례, 목록 3회차:** 실제로 20건을 초과하는 데이터로 기본 페이지 제한을
  확인하고, 같은 소유자 ID여도 다른 테넌트 주문은 제외되는지 검증했습니다.

두 조건 모두 기존 가격·권한 정책을 재사용했고 트랜잭션을 지역적으로 관리했습니다.
정적 검토에서 중대한 구현 결함은 식별하지 못했지만, 결함이 없다는 뜻은 아닙니다.
이 결과는 **일부 테스트 설계가 달랐다는 관찰**이며 스킬의 안정적 개선 효과로
일반화할 수 없습니다. 리뷰 점수를 평균해 보편적인 품질 점수로 만들지 않았습니다.

## 채점 도구도 감사했다

결과물을 보지 않은 별도 감사자는 원래 검사가 좁은 스모크 평가로는 유효하지만,
취소 목록의 실제 항목, 마지막 키 저장 실패의 롤백, 저장된 멱등성 결과 데이터 등에
누락이 있음을 발견했습니다. 원래 검사와 점수는 수정하지 않았습니다.

이후 양쪽 모두에 동일한 **사후 추가 검사**를 적용했습니다. 위 누락 중 일부와 견적의
할인 후 배송·금액 하한을 검사했고, 18개 결과물 모두 통과했습니다. 사후 검사는 원래
평가와 구분해 공개하며 사전 고정된 검사의 일부였다고 소개하지 않습니다.
그럼에도 입력 공간·동시 요청의 모든 순서·실제 운영 DB의 동작을 포괄하지는 않습니다.

## 이 결과의 현실적인 의미

현재 스킬은 개발 원칙과 절차를 공유하는 **실험 단계의 지침**입니다. 이 환경에서는
스킬이 없어도 기본 에이전트가 비슷한 재사용·구현·검증을 수행했습니다. 품질 향상,
검토 시간 절감, 재작업 감소를 입증한 제품으로 소개하면 근거를 넘는 주장입니다.

다음 개선은 원칙을 더 많이 넣는 방식보다, 실제 프로젝트에서 실패한 변경과 리뷰
수정 요청을 수집하고, 범용적인 원인을 고친 뒤 보지 않았던 과제에서 비교하는 방식이
타당합니다. 프로젝트의 금지 의존성·권한·계약 같은 검증 가능한 조건은 지침과 함께
실행 가능한 검사로 고정할 수 있습니다. 이는 후속 개발 방향이며 이번 실험에서
효과가 입증된 처방은 아닙니다. 이번 실행 중에는 스킬을 고쳐 성적을 맞추지 않았습니다.

## 한계와 재현 자료

- 합성 과제 **3종**의 반복입니다. 독립적인 실무 과제 9종이 아니며, 대규모 저장소,
  다른 언어, PostgreSQL 등 실제 운영 DB에서의 일반화는 검증하지 않았습니다.
- 실행 순서는 초안의 무작위 계획과 달리 조건을 번갈아 시작했습니다. 공개 사전등록
  실험이 아니며, 첫 작업자를 실행한 후 결과를 읽기 전에 외부 검사 작성을 마쳤습니다.
  이 차이는 [실행 기록](../fastapi/execution-notes.md)에 보존했습니다.
- 기본 조건도 같은 도구 목록에서 스킬 설명을 볼 수 있습니다. 스킬을 읽지 말라고
  지시했고 작업자 기록은 그렇게 보고하지만, 물리적으로 차단한 실험 환경은 아닙니다.
  전체 도구 기록 대신 작업자의 실행 기록과 실제 산출물을 확보했습니다.
- 코드 검토는 사람이 아닌 AI의 정적 판단입니다. 스타일로 조건을 추측할 가능성을
  완전히 제거하지 못하며, 실제 사람의 검토 시간을 측정하지 않았습니다.
- 정확한 모델 빌드·토큰·정규화된 실행 시간은 완료 메타데이터에 제공되지 않았습니다.
  수치를 추정하거나 알 수 없는 비용을 0으로 처리하지 않았습니다.
- CI의 저장 결과 재검사는 새 AI 실행이 아닙니다. 원래 18회에 더해 세지 않습니다.
